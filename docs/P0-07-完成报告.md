## 实现行为

- `NewManager()`、`NewManager("")` 默认使用 `kernels`；也可以传入内核目录。Windows 自动使用 `.exe`，其他平台使用无后缀文件名。
- `StartSingBox` / `StartMihomo` 启动前分别执行 `sing-box check -c <配置>`、`mihomo -d <配置目录> -f <配置> -t`；校验超时为 10 秒，错误中保留最多 64 KiB 诊断输出。
- 替换配置先完成校验，再停止旧内核；无效配置不会中断当前运行的另一内核。运行参数为 `sing-box run -c <配置>`、`mihomo -d <配置目录> -f <配置>`。
- 默认 `single_switch` 模式下最多管理一个活跃内核；`coexist` 可同时运行两个。从共存切回单核时保留 sing-box，停止 mihomo，包含处于退避中的进程生命周期。
- `StopSingBox`、`StopMihomo`、`StopAll` 均可重复调用。主动停止先禁用重启并取消生命周期上下文；退避等待也会立即取消。
- 每次启动只有一个 `Cmd.Wait` 调用者，负责回收进程、排空日志并发布退出结果。生命周期操作使用独立互斥锁，状态和日志读取不需要等待完整的配置校验或启动健康检查。
- Unix 尝试 SIGTERM，等待超过 5 秒由 `WaitDelay` 强制终止；Windows 直接终止子进程。另有有界停止等待与强制终止兜底。
- 非主动退出（包括退出码 0）触发自动恢复，默认至多尝试 5 次，依次等待 1、2、4、8、16 秒。单次重新启动成功不会重置预算，避免快速崩溃形成无限重启；某次运行存活至少 30 秒后退出时重置预算。
- 重启复用同一日志缓冲区，并保留退出码、退出原因、最近 100 条重启记录。手动开始新的生命周期会建立新缓冲区和重试预算。
- 日志包含时间、来源和内容，容量为 10000 条，按时间顺序返回。支持 CRLF、末尾无换行内容；超过 512 KiB 的单行分块保存，避免管道阻塞和单行缓存无限增长。

## 健康检查

读取 mihomo 的 `external-controller` / `secret`，或 sing-box 的 `experimental.clash_api.external_controller` / `secret`；通配监听地址在本地探测时转换为回环地址，支持 IPv6。

每次启动和自动重新启动时，最多等待 5 秒探测 `/version`。探测绕过环境代理，携带 Bearer 密钥，要求 HTTP 200 且 JSON 中的 `version` 非空。启动失败会回收已启动的进程，自动恢复时的健康失败仍受重试预算约束。

无 Clash API 配置时允许进程运行，状态显示 `health_check_enabled=false`、`healthy=false`。`HealthCheck(ctx, name)` 可由调用方按需执行；尚未增加周期性健康检查定时器。状态中的 `healthy` 表示最近一次探测结果。

主要查询接口为 `Status()`、`GetLogs(name, n)`、`HealthCheck(ctx, name)`，内核名称为 `sing-box` / `mihomo`；为兼容原结构，`Status()` 内 sing-box 的键仍为 `singbox`。日志 `n <= 0` 返回全部保留内容。

## 验证结果

在 Windows amd64 / Go 1.27.0 环境中执行：

```powershell
go test ./internal/kernel -count=1 -coverprofile="$env:TEMP/duorelay-kernel-coverage.out" -timeout 90s
go vet ./internal/kernel
go test -short ./...

$env:DUORELAY_KERNEL_INTEGRATION='1'
go test ./internal/kernel -run '^TestRealKernels$' -v -count=1 -timeout 90s
```

- 内核包测试通过，语句覆盖率 **90.3%**；`go vet` 通过；全仓短测试通过。
- 覆盖双内核启停、重复启动、幂等停止、无效替换配置、模式转换、退出码记录、崩溃/外部强杀/意外正常退出后的恢复、退避取消、连续崩溃上限、重启执行失败、配置校验超时、健康失败回收、API 禁用、并发状态与日志读取、鉴权和错误响应、日志淘汰及超长行边界。
- 真实内核为本地 `sing-box 1.14.4`、`Mihomo Meta v1.19.33`。两个内核均验证了配置校验、启动、带密钥的 `/version`、强杀后恢复、停止、日志捕获和错误配置拒绝。

## 验证限制

- 不带 `-short` 的全仓测试包含已有 `clashapi` 集成用例，要求提前在 `127.0.0.1:19093` / `19094` 启动对应服务。未提供服务时，这些用例因连接拒绝失败；本任务新增的真实内核测试自行管理临时端口和子进程。
- 已尝试 `go test -race ./internal/kernel -count=1 -timeout 120s`。竞态测试二进制在进入测试前以 `0xc0000139` 退出，故本机未取得有效的竞态检测结果；不能据此声称竞态检测通过。
- Unix 信号分支尚未在真实 Unix 运行环境联调。配置版本管理、失败回滚和 TUN 权限处理属于后续阶段。
