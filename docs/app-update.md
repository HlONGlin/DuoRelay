# 关于页检查更新与一键更新

简体中文 | [English](app-update.en.md)

在“设置 → 关于”点击“检查更新”，DuoRelay 会查询 GitHub 最新正式版，并按当前平台与 full/lite 变体匹配发布包。支持的发布包为 Linux amd64/arm64 和 Windows amd64；Linux/Windows 均支持 full 与 lite。若仓库尚无正式版、当前平台没有对应资产或安装目录不可写，页面会显示原因并禁用一键安装。

确认版本与发布说明后，点击“一键更新并重启”。程序在后台下载并验证资产大小与 GitHub 提供的 SHA-256（若资产提供摘要），检查压缩包路径和文件类型，再更新程序与随包内核并重启。节点、设置和数据库保存在各自的数据目录，不会由更新包替换。更新期间不要手动关闭程序。

## 安装方式限制

- **Windows**：当前用户必须能够写入 DuoRelay 程序所在目录。安装在受系统保护的位置时，请使用有权限的部署方式手动更新。
- **Linux 可写目录**：程序目录可写时支持原地更新。更新通过替换当前可执行文件并在原进程中启动新版本完成。
- **Linux 默认 systemd 系统服务**：默认安装路径 `/opt/duorelay` 由 root 管理，systemd 保护该程序目录。关于页仍可检查版本，但会禁用一键安装；请按 [Linux 部署](linux-deployment.md)停止服务、备份并重新安装目标版本。程序不会为了更新而提升服务权限或放宽系统目录保护。
- **Linux 透明代理系统服务**：显式 `--transparent` 模式以 root 运行，并允许该进程写程序目录；发布资产匹配且目录可写时可提供一键更新。程序不会自行将普通服务转换为 root 服务；权限设置见[运维指南](operations.md)。
- **Docker**：通过拉取或重新构建目标镜像更新容器；不要在容器内使用二进制自更新。参见 [Docker 部署](docker-deployment.md)。

自动更新依赖 GitHub 正式版提供与当前包名一致的资产。检查失败或提示尚无正式版时，可稍后重试；也可使用对应平台的部署文档手动升级。
