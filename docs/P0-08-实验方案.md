# P0-08 UDP共存实验方案

## 任务背景

这是P0阶段的**关键风险验证任务**，决定了P2阶段双核共存的实现方式。

## 实验目标

验证UDP协议（TUIC、Hysteria2）能否通过SOCKS5链式转发工作，以支持主从共存模式。

## 实验假设

**假设1（理想情况）**：UDP可以通过SOCKS5转发
- TUIC节点 → SOCKS5代理（mihomo/sing-box提供） → 目标
- 实现方案：主核处理TCP，从核处理UDP，通过SOCKS5互联

**假设2（降级方案）**：UDP无法通过SOCKS5转发
- 必须使用单核切换模式
- 独有协议节点触发内核切换

## 实验设计

### 环境准备
1. 启动本地TUIC测试服务器（Docker）
2. 启动sing-box作为SOCKS5代理（端口1080）
3. 客户端配置TUIC通过SOCKS5转发

### 测试用例

#### TC1: TUIC over SOCKS5
```yaml
测试: TUIC客户端 → SOCKS5(1080) → TUIC服务器 → 目标
预期: UDP数据包能够成功转发
验证: curl --socks5 127.0.0.1:1080 http://example.com
```

#### TC2: Hysteria2 over SOCKS5
```yaml
测试: Hysteria2 → SOCKS5 → 目标
预期: 同TC1
```

#### TC3: DNS over UDP through SOCKS5
```yaml
测试: DNS查询(UDP) → SOCKS5 → DNS服务器
预期: DNS解析成功
```

### 实验步骤

1. **准备测试环境**
   ```bash
   # 启动TUIC测试服务器
   docker run -d --name tuic-test tuic-server
   
   # 启动sing-box作为SOCKS5代理
   ./kernels/sing-box.exe run -c testdata/configs/socks5-proxy.json
   ```

2. **配置TUIC客户端**
   ```json
   {
     "outbound": {
       "type": "tuic",
       "server": "127.0.0.1",
       "server_port": 8443,
       "detour": "socks5-out"  // 通过SOCKS5转发
     }
   }
   ```

3. **执行测试**
   - 测试连接性
   - 测试传输性能
   - 抓包验证UDP封装

4. **记录结果**
   - 成功/失败
   - 错误信息
   - 性能数据

## 预期结果与决策

### 如果实验成功（UDP可转发）
**结论**: 采用主从共存模式
- P2实现：主核处理TCP，从核处理独有UDP协议
- 架构：两个内核同时运行，通过SOCKS5互联
- 优点：无缝支持所有协议
- 缺点：资源占用略高

### 如果实验失败（UDP不可转发）
**结论**: 采用单核切换模式
- P2实现：独有协议触发内核切换
- 架构：同一时间只有一个内核运行
- 优点：资源占用低
- 缺点：切换有延迟，不能混用
