## API

订阅接口：

- `GET/POST /api/subscriptions`
- `GET/PUT/DELETE /api/subscriptions/:id`
- `POST /api/subscriptions/:id/update`
- `GET /api/subscription-groups`

节点和测速接口：

- `GET/POST /api/nodes`
- `DELETE /api/nodes/:id`
- `POST /api/nodes/:id/test`
- `POST /api/nodes/:id/activate`
- `POST /api/speedtest/batch`
- `GET/DELETE /api/speedtest/tasks/:id`

配置和内核接口：

- `GET/PUT /api/config`
- `GET /api/config/current`
- `POST /api/config/apply`
- `GET /api/kernel/status`
- `POST /api/kernel/start`（按请求体调用配置 apply）
- `POST /api/kernel/stop`
- `GET /api/kernel/logs`
- `GET /api/kernel/connections`

所有接口使用既有 `{success,data,error}` 响应封装，输入 JSON 禁止未知字段，响应不会暴露生成配置路径、控制器密钥或数据库中的加密 URL。

## 订阅行为

- 支持直链、标准/无填充/URL-safe Base64、Clash YAML、sing-box JSON 和分享链接列表。
- 默认使用 `parser/defaults.New()` 注册现有 Shadowsocks、VMess、VLESS、Trojan、Hysteria2、TUIC 解析器。
- URL 使用 AES-256-GCM 存储，密钥保存在数据库文件旁的权限为 0600 的 `.key` 文件；`:memory:` 数据库使用进程内随机密钥。请求返回时解密 URL，数据库 payload 不包含明文 URL。
- 更新先下载、限制 16 MiB、解析全部节点，成功后在事务中替换订阅节点；失败只更新错误状态和下一次重试时间，旧节点和手动节点保留。
- 节点 ID 由订阅 ID、协议、名称、服务器和端口生成稳定摘要，更新时保留收藏、标签、排序和测速信息。响应提供新增、删除、变更计数。
- `subscription-userinfo` 支持 upload、download、total、expire；用量溢出会饱和到 `MaxInt64`。
- 调度器读取持久化 `NextUpdate`，默认每分钟检查一次；失败采用 1 分钟起、最多 6 小时的指数退避。

## Speedtest 行为

- TCP 测速只建立到节点服务器的 TCP 连接。
- HTTP 测速需要显式节点 HTTP 代理或由应用注入活动内核的 Clash API 探测；禁止静默降级成直连。目标 URL 仅允许 HTTP/HTTPS，超时范围为 1 至 60000 毫秒，默认 5000 毫秒。
- 批量测速去重节点 ID，最多 10000 个，使用任务队列保存状态、进度和结果。每批最多 4 个并发测试；单项结果保存到 `speedtest_results`。

## 配置应用行为

- 由 IR 节点和生成器生成 sing-box JSON 或 mihomo YAML。
- 写入控制器地址和随机密钥后调用 `sing-box check` / `mihomo -t`，校验失败不会停止当前内核。
- 新内核启动失败时停止失败进程并尝试恢复之前保存的配置；当前状态只在启动成功后持久化。
- `/api/nodes/:id/activate` 生成只包含目标节点的配置，并将默认出站切换到该节点。
- API 进程默认监听 `127.0.0.1:8080`，可通过 `-listen`、`-db`、`-kernels`、`-config-dir`、`-workers` 调整。

限制：

- `go test ./...` 中仓库已有 `internal/clashapi` 集成测试要求外部服务预先监听 `127.0.0.1:19093` 和 `127.0.0.1:19094`；未提供时仅这些用例因连接拒绝失败，其余包通过。
- Windows 上新增后端包的 `go test -race` 二进制在执行测试前以 `0xc0000139` 退出，未将其标记为通过。
- WebSocket 实时日志未实现；HTTP 日志查询已实现。节点协议解析能力取决于当前 parser registry 已注册的协议。
- 批量任务状态保存在内存队列中，单项测速历史和节点最新测速值持久化到 SQLite；重启后不能继续查询旧任务 ID。
- HTTP 测速通过 Clash API 时要求目标节点包含在当前生成配置中；未激活的其他协议节点仍可执行 TCP 测速。
- 回滚以先前成功应用的配置为目标；尚未应用过配置时，首次启动失败只清理失败进程。配置应用会停止所有受当前 Manager 管理的内核，再启动选定内核。
