# 链式代理兼容适配验收

日期：2026-11-01。

## 已实现

- 取消前端协议白名单，改由后端按节点参数、内核支持和逐跳 TCP/UDP 能力规划，支持 2–8 个不同节点。
- 优先单核，必要时通过带随机认证的本机 SOCKS5 桥接连接 sing-box 与 mihomo，支持多次交替跨核。
- 弹窗显示每跳内核、连接传输、整链 UDP 能力和不兼容原因；预览期间及不可用时禁止启动。
- 生成并校验全部配置后才切换运行实例，启动失败恢复前一份完整配置；停止时清理主辅配置。
- 公共接口隐藏控制器凭据、桥接认证和内部路径；跨核运行状态以主内核为准。
- 保留大陆绕过、黑名单直连默认值及仅 SOCKS5 入口使用代理的规则，防止用户规则绕过中间节点。
- 修正 MASQUE 内核归属、ShadowQUIC 密码认证、VMess 默认字段、Hysteria v1 认证字段和虚拟组网节点存储校验。
- 补齐 Windows Naive 的固定版本 Cronet DLL 安装脚本、版本锁和 SHA256 校验。

## 验证结果

- `go test ./...`、`go vet ./...` 通过；收尾修改后 API、配置模块和黑名单默认出口测试通过。
- 固定版本真实内核配置矩阵验证 27 种网络/传输协议的可用入口与出口位置。
- 本地真实 TCP 流量验证同核、双向跨核、8 跳交替跨核及 SOCKS5 入口隔离；桥接拒绝匿名认证。
- 两个本地加密 Shadowsocks 服务与 UDP 回显验证四种内核组合的真实 UDP 链路。
- 前端 42 项测试、类型检查、生产构建通过。
- 浏览器交互验证 Naive → Mieru 双核预览可启动，HTTP → Hysteria2 显示第二跳缺少 UDP 的原因并禁用启动。
- API 测试验证预览无运行副作用、响应不泄露凭据，以及主内核停止时不会把辅助内核报告为活动出口。
- 正常开发服务已使用更新后的后端启动，5173 页面、8080 API 和经 5173 转发的 API 均返回 HTTP 200，新预览端点可达；临时测试服务已关闭。

## 实际限制

Rematch 是路由适配器，不能充当独立代理跳。ShadowTLS 必须与后续 Shadowsocks 配套。后续跳需要 UDP 时，前段链路必须能承载 UDP；VPN/组网出口权限取决于远端配置。以上本地测试不代表所有用户远端节点均已连通，未通过 TUN 接管用户系统网络。

使用说明与复现命令见 [多节点代理说明](multi-node-proxy.md)。
