# ADR-002: 双核共存架构决策

简体中文 | [English](ADR-002-dual-kernel-coexistence.en.md)

## 状态

✅ 已决策

## 上下文

DuoRelay支持28种代理协议，分布在sing-box和mihomo两个内核：
- 14种共同协议（两核都支持）
- 4种sing-box独有
- 10种mihomo独有

需要决定如何处理两核独有协议的运行方式。

## 决策

**采用单核切换模式，不实现双核并行共存。**

当用户选择的节点需要不同内核时：
1. 停止当前运行的内核
2. 重新生成目标内核配置
3. 启动目标内核
4. 通知用户"内核已切换"

## 理由

### 技术可行性分析

#### 方案1: 主从共存（UDP通过SOCKS5转发）

**原理**：
- 主核处理共同协议
- 从核处理独有协议
- 通过SOCKS5代理链互联

**技术挑战**：
1. **UDP over SOCKS5复杂**
   - SOCKS5的UDP ASSOCIATE需要客户端明确支持
   - TUIC/Hysteria2基于QUIC（UDP），通过SOCKS5中继需要特殊处理
   - QUIC的连接迁移特性与SOCKS5代理冲突

2. **性能损失**
   - UDP通过TCP隧道会增加延迟
   - 额外的封装/解封装开销

3. **可靠性问题**
   - NAT穿透困难
   - 双核运行的故障点增多

#### 方案2: 单核切换

**原理**：
- 同一时间只运行一个内核
- 根据节点协议选择内核
- 切换时停止旧核、启动新核

**优点**：
- ✅ 实现简单可靠
- ✅ 资源占用低（单核约150MB内存）
- ✅ 兼容性好（无需UDP中继）
- ✅ 性能最优（无额外代理层）
- ✅ 故障点单一，易调试

**缺点**：
- ⚠️ 切换有2-3秒延迟（配置校验+进程启停）
- ⚠️ 不能同时使用两核的独有协议

### 实际场景分析

**用户使用场景**：
1. 大多数用户只使用常见协议（SS/VMess/Trojan）- **无需切换**
2. 少数用户使用独有协议，但通常不会频繁切换
3. 切换发生在**节点选择时**，而非每个请求

**切换频率评估**：
- 用户选择节点后通常会使用较长时间（数小时到数天）
- 切换场景：测试不同节点、特定协议需求
- **频率：低**（每天0-2次）

**2-3秒延迟可接受性**：
- ✅ 节点切换本身就需要等待连接建立
- ✅ 用户预期内的操作反馈时间
- ✅ 可通过UI提示优化体验

### v2rayA对标

v2rayA仅支持单核（Xray），无需切换。DuoRelay支持双核已经是**功能提升**。

## 决策结果

### P2实现计划

1. **内核选择逻辑**（P2-05）
   ```go
   func SelectKernel(node *ir.Node) ir.KernelType {
       if node.Owner == ir.KernelSetBoth {
           return currentKernel // 保持当前内核
       }
       return node.Owner.PreferredKernel()
   }
   ```

2. **切换流程**（P2-06）
   - 检测是否需要切换
   - 停止当前内核
   - 生成新配置
   - 启动目标内核
   - 验证健康状态
   - 通知前端更新状态

3. **用户体验优化**（P2-07）
   - 显示"正在切换内核（sing-box → mihomo）..."
   - 进度条或加载动画
   - 切换完成后toast通知
   - 节点列表标注所需内核

### 未来扩展

如果用户强烈要求双核共存，可以在V2.0实现**有限共存模式**：
- TCP协议支持主从共存
- UDP协议仍然触发切换
- 作为高级功能，默认关闭

## 影响

### 对其他模块的影响

- **generator**: 只需生成单个内核的配置 ✅
- **kernel manager**: 已支持单核切换模式 ✅
- **API**: 增加内核切换接口
- **前端**: 显示切换状态和当前内核

### 性能影响

- **内存**: 150MB（单核）vs 300MB（双核共存）
- **CPU**: 基本无影响
- **切换延迟**: 2-3秒

### 用户体验影响

- **常见场景**: 无影响（使用共同协议）
- **独有协议**: 2-3秒切换时间
- **整体**: 可接受

## 备选方案

### 备选1: 双核完全共存

- 两个内核同时运行
- 通过端口分配区分
- **不采用**：UDP转发问题无法优雅解决

### 备选2: 混合模式

- TCP协议共存，UDP协议切换
- **不采用**：实现复杂，用户难以理解
